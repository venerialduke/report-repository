# Insights Hub — Build Plan

A central, static home for the Insights team's HTML reports, hosted on GitHub Pages.

## Guiding principles

1. **Reports stay plain HTML.** An analyst can drop a folder into `reports/` and it works. No framework lock-in.
2. **Metadata lives beside the report** (`report.json`) and is validated in CI, so the catalog stays trustworthy.
3. **No server required.** Everything that needs a backend (AI, comments) degrades gracefully and has a documented upgrade path.
4. **Shared brand, shared charts.** Reports link `shared/brand/report.css` and `shared/brand/charts.js` so they look consistent and render in bundles and PDFs.

## Architecture

```
index.html              Landing: search, What's New carousel, area carousels, tag/type filters
report.html?id=<slug>   Viewer: report in an iframe + metadata rail, PDF, AI summary, comments
bundle.html?ids=a,b     Printable bundle of several reports (one PDF, page breaks between)
resources.html          Shared assets: brand kit, templates, Claude skills
catalog.json            GENERATED: metadata for every report (scripts/build-catalog.mjs)
search-index.json       GENERATED: plain-text body of every report (full-text search + AI context)
site.config.json        Site name, team code repo, comments (giscus) config, AI defaults
reports/<slug>/         index.html + report.json (+ any local assets)
shared/brand/           tokens.css, report.css, charts.js, logo, brand guide
shared/templates/       report-starter (copy me)
.claude/skills/         Claude skills: report construction, storytelling review, viz review, brand style
scripts/                build-catalog, validate, new-report, generate-summaries
.github/workflows/      CI (validate on PR) + Pages deploy (build + publish on main)
```

### Report metadata (`report.json`)

| field | req | notes |
|---|---|---|
| `id` | ✓ | equals folder name, kebab-case |
| `title`, `subtitle` | ✓ / – | |
| `type` | ✓ | `report` \| `article` |
| `area` | ✓ | one of the areas in `site.config.json` |
| `topics` | ✓ | broader themes, e.g. "Retention" |
| `tags` | ✓ | fine-grained keywords |
| `owners` | ✓ | `[{name, email, role}]` |
| `published`, `updated` | ✓ / – | ISO dates |
| `status` | ✓ | `final` \| `draft` \| `superseded` |
| `summary` | ✓ | 1–3 sentence author summary |
| `key_findings` | – | array of short statements |
| `code` | – | `[{label, path}]` — path is relative to `teamRepo` in config, or a full URL |
| `data_sources` | – | array of strings |
| `related` | – | array of report ids |
| `ai_summary` | – | generated by `scripts/generate-summaries.mjs` (never hand-edited) |

### AI summaries

- **Pre-generated** summaries: `scripts/generate-summaries.mjs` runs in the Pages workflow if an `ANTHROPIC_API_KEY` repo secret exists, and writes `ai_summary` into the catalog. Zero cost to readers, no key in the browser.
- **On-demand** (single report, a selection of reports, or a free-form question across a selection): runs in the browser with the Anthropic JS SDK using the reader's own API key (kept in their `localStorage`, sent only to api.anthropic.com).
- **No key?** "Copy prompt" builds the same prompt with the report text so it can be pasted into Claude.
- **Upgrade path:** a small proxy (Cloudflare Worker / internal gateway) holding a team key → set `ai.proxyUrl` in config.

### Comments

- **giscus** (GitHub Discussions) when `comments.giscus` is configured in `site.config.json`. One discussion per report id.
- Otherwise a **local prototype mode** (stored in the reader's browser only), clearly labelled.

### PDF export

- Single report: the viewer prints the report iframe; `report.css` carries a print stylesheet (page size, running header, avoid breaking figures).
- Multiple reports: `bundle.html` fetches each report, stacks them with a cover page and table of contents, re-renders charts, then prints.

## Later / not in the prototype

- SSO-gated hosting (GitHub Pages on a private repo requires Enterprise; alternatives: Cloudflare Access, internal static host).
- Per-report view analytics, "most read" carousel.
- Versioning / report history UI (git already has it; surface `updated` + a changelog link).
- Subscriptions ("notify me when Area X publishes") via GitHub watch or an RSS feed (`feed.xml` is cheap to add to the build).
- Server-side AI proxy with a shared team key and usage limits.
- Semantic (embedding) search.
